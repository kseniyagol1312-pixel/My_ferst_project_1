# Ограничения и развитие

## Что сознательно не реализовано

Исключено по ТЗ для демонстрационной версии:

- backend, база данных, сущности, API, коннекторы, внешние сервисы;
- авторизация и роли;
- AI/LLM-вызовы, AI-агенты, извлечение данных из файлов, имитация работы AI;
- загрузка файлов (резюме, транскрипты, отчеты тестов);
- отправка email;
- создание, удаление и изменение весов критериев;
- лендинг, onboarding, тарифы, чат, административная панель.

## Технические ограничения прототипа

| Ограничение | Последствие |
|---|---|
| Данные в `localStorage` | Видны только в одном браузере на одном устройстве; совместной работы нет; очистка данных сайта удаляет все изменения |
| Одна вакансия | Справочник `VACANCY` и критерии зашиты в код |
| Нет истории изменений | Нельзя увидеть, кто и когда менял оценку |
| Нет удаления | Кандидата, интервью и тест нельзя удалить из интерфейса (только полным восстановлением демоданных) |
| Карьерная история только у демокандидатов | В форме кандидата нет полей истории |
| Интервью не влияют на оценку критерия | Связь интервью с критерием информационная; перенос вывода в оценку делает рекрутер вручную |
| Схема без версий | При изменении структуры данных нужно менять `LS_KEY` |
| Полная перерисовка экрана | На сотнях кандидатов станет заметно медленно; для 3–20 незаметно |

## Этические рамки

Заложены в модель данных и интерфейс:

- Нет полей и расчетов по возрасту, фото, полу, национальности, семейному положению, внешности, мимике, голосу, эмоциям, «энергии» и психологическим диагнозам.
- Вместо фото — нейтральные инициалы.
- Оценка требует источника и конкретного факта; бессодержательные формулировки не поощряются подсказкой в форме.
- Частота смены работы показывается как нейтральный факт без оценки.
- Термин «рыночная стоимость кандидата» не используется, только сравнение с бюджетом вакансии.
- Ни один статус не отклоняет кандидата и не меняет этап; победитель в сравнении не выбирается.
- Подпись «Система структурирует данные и помогает сравнивать кандидатов. Решение принимает человек» стоит во всех итоговых блоках.

**Важно для продакшена.** Прототип не проходил юридической проверки. Перед работой с реальными персональными данными кандидатов нужно проверить требования законодательства о персональных данных той страны, где будет использоваться продукт (для Казахстана — действующую редакцию закона о персональных данных и их защите), у юриста или по первоисточнику. Хранение реальных резюме в `localStorage` для продакшена не подходит.

## Заглушки «Следующий этап»

| Функция | Что нужно для реализации |
|---|---|
| Настройка критериев | Хранилище вакансий, редактор критериев с проверкой суммы весов = 100% |
| Загрузка резюме PDF/DOCX | Защищенное хранилище файлов, извлечение текста, при желании AI-разметка фрагментов с подтверждением человеком |
| Загрузка транскрипта | Хранилище, привязка фрагментов транскрипта к критериям |
| Загрузка отчета тестирования | Хранилище или интеграция с платформой тестирования |

## Возможные следующие шаги

Порядок не согласован с заказчиком, это предложение:

1. Серверное хранение и авторизация (без этого продукт нельзя использовать командой).
2. Несколько вакансий и редактор критериев.
3. Журнал изменений оценок (кто, когда, что было).
4. Удаление и архивирование кандидатов, интервью, тестов.
5. Редактирование карьерной истории.
6. Экспорт сводки и сравнения.
7. Загрузка файлов и извлечение данных из них.
