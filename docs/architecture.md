# Архитектура

## Файлы

```
index.html          — всё приложение: разметка, стили, скрипт
docs/               — техническая документация
DefaultCatchBoundary.jsx — отдельный React-компонент, к прототипу не относится
```

## Структура `index.html`

| Блок | Что внутри |
|---|---|
| `<head>` | `<title>`, viewport, подключение шрифта Inter, `<style>` со всеми стилями |
| `<header class="topnav">` | Статическая верхняя навигация: название, бейдж Demo, вкладки, вакансия, меню «⋯» |
| `<main id="main">` | Контейнер текущего экрана (перерисовывается целиком) |
| `<div id="drawer-root">` | Правая панель: карточка кандидата или панель ячейки матрицы |
| `<div id="modal-root">` | Модальные окна: формы, информационные окна, подтверждение |
| `<div id="toasts">` | Всплывающие уведомления (`aria-live="polite"`) |
| `<script>` | Весь код в одной IIFE со `'use strict'` |

## Слои скрипта

Код разбит комментариями-разделителями `/* ---------- ... ---------- */` в таком порядке:

1. **Справочники** — `LS_KEY`, `VACANCY`, `CRITERIA`, `STAGES`, `EV_SOURCES`, `EV_STATUS`, `SCORE_TEXT` и др. См. [data-model.md](data-model.md).
2. **Демоданные** — `demoData()` возвращает новый объект состояния с тремя кандидатами; фабрики `ev()`, `noData()`, `emptyEvals()`.
3. **Хранение** — `load()` / `save()`, чтение и запись `localStorage` в `try/catch`.
4. **Утилиты** — экранирование `esc()`, форматирование `tenge()`, `pct()`, `fmtDate()`, `dur()`, `plural()`, генерация id `uid()`, иконки `ICON`.
5. **Расчеты** — `metrics()`, `budgetFit()`, `needsWarning()`, `tone()`, `careerFacts()`, `analysis()`. Чистые функции, только читают данные кандидата. См. [calculations.md](calculations.md).
6. **Рендер** — функции, возвращающие HTML-строки: `workspace()`, `viewCandidates()`, `viewMatrix()`, `viewCompare()`, `candidatePanel()`, вкладки `tabOverview()`, `tabEval()`, `tabInterviews()`, `tabSummary()`, `cellPanel()`.
7. **Модальные окна и формы** — `openModal()`, `closeModal()`, `info()`, конструкторы полей `fld()`, `inp()`, `sel()`, `ta()`, формы `candidateForm()`, `evalForm()`, `interviewForm()`, `testForm()`.
8. **Действия** — `toggleSel()`, `copyText()`, `summaryText()`.
9. **События** — делегированные обработчики `click`, `input`, `change`, `keydown` на `document`.

## Состояние

Есть два объекта:

- `state` — **персистентные данные**: `{candidates: [...], selected: [...]}`. Сохраняются в `localStorage` после каждого изменения вызовом `save()`.
- `ui` — **состояние интерфейса**, не сохраняется: текущий экран, поиск и фильтры, открытая карточка и вкладка, выбранная ячейка матрицы, режимы матрицы, открыто ли меню.

```js
ui = {view, search, stage, openId, tab, cell, mSearch, reqOnly, mode, menu}
```

После перезагрузки страницы приложение всегда открывается на экране «Кандидаты», а данные и выбор для сравнения восстанавливаются.

## Цикл рендера

Виртуального DOM нет: экран пересобирается из HTML-строк.

```
действие пользователя → изменение state/ui → save() (если менялся state) → renderAll()
renderAll() = renderNav() + renderMain() + renderDrawer()
```

- `renderNav()` — только переключает классы активной вкладки и видимость меню.
- `renderMain()` — пересобирает `#main`, затем дорисовывает таблицу (`renderCandTable()` или `renderMatrixTable()`).
- `renderDrawer()` — пересобирает правую панель. Если открыт тот же кандидат на той же вкладке, сохраняет прокрутку тела панели. Пока панель открыта, у `body` блокируется прокрутка.

**Поиск без потери фокуса.** Ввод в поле поиска перерисовывает только таблицу (`renderCandTable()` / `renderMatrixTable()`), а не весь экран, поэтому курсор остается в поле.

Все пользовательские строки проходят через `esc()` перед вставкой в HTML, чтобы ввод не ломал разметку.

## Обработка событий

Один обработчик `click` на `document` ищет ближайший элемент с атрибутом `data-act` и выполняет действие по `switch`. Параметры передаются через `data-id`, `data-crit`, `data-view`, `data-v`, `data-k`.

| `data-act` | Действие |
|---|---|
| `view` | Переключить экран |
| `menu`, `restore` | Меню и восстановление демоданных (с подтверждением) |
| `criteria-info` | Информационное окно «Настроить критерии» |
| `add-cand`, `edit-cand` | Форма кандидата |
| `open` | Открыть карточку кандидата |
| `toggle-sel` | Добавить или убрать кандидата из сравнения |
| `go-compare` | Перейти к сравнению (при 2–3 выбранных) |
| `reset-filters`, `reset-msearch` | Сбросить поиск и фильтры |
| `req`, `mode` | Переключатели матрицы |
| `cell` | Открыть панель ячейки матрицы |
| `dtab` | Вкладка карточки |
| `edit-eval`, `add-int`, `add-test` | Формы оценки, интервью, теста |
| `info` | Заглушки загрузки (`resume`, `transcript`, `testreport`) |
| `copy-summary`, `cmp-from-card` | Действия вкладки «Сводка» |
| `close-drawer`, `close-modal`, `modal-bg` | Закрытие панелей и окон |

Чекбокс внутри строки таблицы имеет собственный `data-act="toggle-sel"`. `closest()` находит его раньше строки, поэтому клик по чекбоксу не открывает карточку.

Прочие обработчики:

- `input`: поля `#cand-search` и `#m-search`.
- `change`: фильтр этапа `#stage-filter` и смена этапа в карточке `#stage-select`.
- `keydown`: `Escape` закрывает окно → меню → панель (по приоритету); `Enter` на строке таблицы открывает карточку.

## Модальные окна

`openModal({title, body, onSubmit, onMount, info, danger, wide, badge, submitLabel})` рисует `<form>` в `#modal-root`.

- `onSubmit(data, form)` получает значения полей из `FormData`. Если возвращает объект `{поле: сообщение}`, ошибки показываются под полями, окно остается открытым, фокус переходит на первое ошибочное поле. Если возвращает пустой результат, окно закрывается.
- `onMount(form)` подключает живую логику: скрытие полей при «Нет данных», расчет процента теста.
- `info: true` — окно с одной кнопкой «Понятно».

Одновременно открыто только одно модальное окно. Системные `alert/confirm/prompt` не используются: подтверждение восстановления демоданных сделано своим модальным окном.
