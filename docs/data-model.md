# Модель данных

## Хранение

| Параметр | Значение |
|---|---|
| Хранилище | `window.localStorage` |
| Ключ | `cem_demo_state_v1` |
| Формат | JSON-сериализация объекта `state` |
| Когда пишется | После каждого изменения: кандидат, этап, оценка, интервью, тест, выбор для сравнения, восстановление демоданных |
| Первый запуск | Ключа нет или JSON поврежден → загружается `demoData()` и сразу сохраняется |

`load()` проверяет, что в JSON есть массив `candidates`. Если `selected` отсутствует, подставляется пустой массив. Ошибки доступа к `localStorage` (приватный режим, запрет cookies) перехватываются: приложение работает, но изменения не переживут перезагрузку.

Данные живут **только в текущем браузере на текущем устройстве**. Синхронизации между пользователями и устройствами нет.

## Корневой объект `state`

```js
{
  candidates: Candidate[],
  selected: string[]   // id кандидатов для сравнения, не больше 3
}
```

## Candidate

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `id` | string | да | Демо: `c-anna`, `c-max`, `c-diana`. Новые: `c-<время><случайность>` |
| `name` | string | да | Имя и фамилия |
| `position` | string | да | Текущая должность |
| `location` | string | — | Локация |
| `email` | string | — | Проверяется простым шаблоном, если заполнен |
| `source` | string | — | Значение из `CAND_SOURCES` или пусто |
| `stage` | string | да | Значение из `STAGES` |
| `salary` | number \| null | — | Зарплатные ожидания в тенге |
| `startDate` | string | — | Дата выхода, `YYYY-MM-DD` |
| `comment` | string | — | Общий комментарий |
| `resume` | string | — | Текст резюме |
| `history` | CareerRow[] | — | Карьерная история; у новых кандидатов пустая |
| `evals` | Record<criterionId, Evaluation> | да | Оценки по всем 9 критериям |
| `interviews` | Interview[] | — | Интервью |
| `tests` | TestResult[] | — | Результаты тестов |

Полей для возраста, фото, пола, национальности, семейного положения нет намеренно.

## Evaluation

```js
{ score: 1..5 | null, status: 'confirmed'|'check'|'conflict'|'none', source, fact, comment, question }
```

| Поле | Описание |
|---|---|
| `score` | `null` означает «Нет данных». Это не ноль |
| `status` | Статус доказательности (см. `EV_STATUS`) |
| `source` | Значение из `EV_SOURCES`; пусто при «Нет данных» |
| `fact` | Конкретный факт или короткая цитата |
| `comment` | Комментарий рекрутера |
| `question` | Вопрос для проверки на следующем интервью |

Инвариант, который поддерживает форма: если `score` задан, то `source` и `fact` заполнены. Если `score === null`, то `status === 'none'`, а `source` и `fact` пусты.

## CareerRow

```js
{ company, role, start: 'YYYY-MM', end: 'YYYY-MM' | null, achievement }
```

`end: null` — текущее место работы. Редактирование истории в интерфейсе не реализовано, история есть только у демокандидатов.

## Interview

```js
{ id, type, date: 'YYYY-MM-DD', interviewer, question, answer, observation, criterion, score: 1..5 | null, nextQuestion }
```

`criterion` — id критерия или пустая строка («Не связан»). Оценка интервью **не меняет** оценку критерия автоматически.

## TestResult

```js
{ id, name, date: 'YYYY-MM-DD', score: number, max: number, criterion, comment }
```

Процент не хранится, считается при отображении: `score / max × 100`.

### Прочие списки

| Константа | Значения |
|---|---|
| `STAGES` | Новый, Скрининг, Интервью, Интервью с менеджером, Финальное интервью, Резерв, Отклонен |
| `FINAL_STAGES` | Интервью с менеджером, Финальное интервью (для показателя «Финалистов») |
| `EV_SOURCES` | Резюме, HR-интервью, Интервью с менеджером, Тест, Рекомендация, Заметка рекрутера |
| `CAND_SOURCES` | LinkedIn, hh.kz, Рекомендация сотрудника, Прямой поиск, Сайт компании, Другое |
| `EV_STATUS` | Подтверждено, Требует проверки, Противоречивые данные, Нет данных |
| `SCORE_TEXT` | 1 — подтвержденное несоответствие … 5 — значительно превосходит ожидание |
| `INTERVIEW_TYPES` | HR-интервью, Интервью с менеджером, Кейс-интервью, Финальное интервью |

## Демоданные

| Кандидат | Должность | Этап | Fit | Coverage | Ожидания | Бюджет | Статус |
|---|---|---|---|---|---|---|---|
| Анна Соколова | Senior Product Manager | Финальное интервью | 84% | 85% | 2 600 000 ₸ | В бюджете | Сильное соответствие |
| Максим Орлов | Product Lead | Интервью с менеджером | 78% | 65% | 3 100 000 ₸ | Выше бюджета | Нужно проверить |
| Диана Ким | Product Manager | Скрининг | 85% | 40% | 2 300 000 ₸ | В бюджете | Нужно проверить |

Все имена, компании (NovaPay Labs, Qadam Digital, Orbit Commerce, Meridian Tech) и email вымышлены. По умолчанию к сравнению выбраны Анна и Максим.

**Отклонение от ТЗ.** В ТЗ указано «около 86% / 41%» для Дианы и «около 82%» Coverage для Анны. При весах, кратных 5, Coverage может принимать только значения, кратные 5. Для Дианы при Coverage 40% Fit может быть 85% или 88%, а 86% недостижим. Выбраны ближайшие корректные значения.

## Миграции

Версионирования схемы нет. При несовместимом изменении структуры нужно сменить `LS_KEY` (например, на `cem_demo_state_v2`): старые данные будут проигнорированы, загрузятся демоданные.
