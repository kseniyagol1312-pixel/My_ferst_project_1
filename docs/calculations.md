# Расчеты

Все расчеты выполняются в браузере функциями из блока «Расчеты» в `index.html`. Пересчет происходит при каждой перерисовке, кэша нет.

## Fit Score — `metrics(c).fit`

Насколько кандидат соответствует вакансии **по тем критериям, где есть оценка**.

```
для каждого критерия с оценкой 1..5:
    weightedPoints = вес × оценка / 5
Fit Score = Σ weightedPoints / Σ весов оцененных критериев × 100
```

- Округление: `Math.round` до целого процента.
- Критерии с «Нет данных» **исключаются** и из числителя, и из знаменателя. Ноль за них не ставится.
- Если не оценен ни один критерий, Fit Score равен `null` и отображается как «—». Деления на ноль и `NaN` нет.
- В Fit входят оценки без источника, если такие появятся (формой это не допускается).

## Evidence Coverage — `metrics(c).coverage`

Какая доля вакансии (по весу) подкреплена данными.

```
Evidence Coverage = Σ весов критериев, где есть оценка И заполнен источник
```

Сумма весов равна 100, поэтому сумма весов — это сразу процент. Coverage считается **независимо от Fit**: высокий Fit при низком Coverage означает, что оценка держится на малом объеме данных.

## Пример: Анна Соколова (демоданные)

| Критерий | Вес | Оценка | w × s / 5 | В Coverage |
|---|---|---|---|---|
| Продуктовая стратегия | 20 | 5 | 20 | да |
| Discovery | 15 | 4 | 12 | да |
| Аналитика | 15 | 4 | 12 | да |
| Delivery | 10 | 4 | 8 | да |
| Команда и стейкхолдеры | 15 | 4 | 12 | да |
| Принятие решений | 10 | нет данных | — | нет |
| Отраслевой опыт | 5 | нет данных | — | нет |
| Английский | 5 | 3 | 3 | да |
| Мотивация | 5 | 4 | 4 | да |
| **Итого** | **85 оценено** | | **71** | **85** |

Fit = 71 / 85 × 100 = 83,5 → **84%**. Coverage = **85%**.

## Предварительный статус — `metrics(c).status`

Правила проверяются строго по порядку, срабатывает первое подходящее.

| # | Условие | Статус | Цвет |
|---|---|---|---|
| 1 | Любой обязательный критерий имеет оценку 1 или 2 | Есть критический риск | красный |
| 2 | Coverage < 70% **или** по обязательному критерию нет данных | Нужно проверить | янтарный |
| 3 | Fit ≥ 80% (и п. 1–2 не сработали) | Сильное соответствие | зеленый |
| 4 | Остальные случаи | Можно рассматривать | синий |

Ни один статус не меняет этап кандидата и не отклоняет его. Этап меняет только человек.

Новый кандидат получает статус «Нужно проверить» автоматически, потому что его Coverage равен 0%.

## Предупреждение о недостатке данных — `needsWarning(m)`

```
Fit ≥ 75% И Coverage < 60%
```

Текст в таблице кандидатов и карточке: «Высокий предварительный балл, но недостаточно подтвержденных данных». На экране «Сравнение» и во вкладке «Сводка»: «Вывод предварительный: требуется дополнительная проверка».

Порог «высокого» Fit (75%) в ТЗ не задан и выбран для прототипа. Меняется в одном месте, в функции `needsWarning`.

## Соответствие бюджету — `budgetFit(salary)`

| Условие | Результат |
|---|---|
| Ожидания не указаны или ≤ 0 | Не указано |
| Ожидания > 2 800 000 ₸ | Выше бюджета |
| Ожидания < 2 000 000 ₸ | Ниже нижней границы |
| Иначе (границы включительно) | В бюджете |

## Цвет ячейки и карточки оценки — `tone(e)`

| Условие (по порядку) | Цвет |
|---|---|
| Нет оценки | серый |
| Оценка 1–2 | красный |
| Статус «Требует проверки» или «Противоречивые данные» | янтарный |
| Оценка 3 | синий |
| Оценка 4–5 | зеленый |

Риск (1–2) важнее статуса проверки: подтвержденное несоответствие всегда красное.

## Карьерные факты — `careerFacts(c)`

Считаются по строкам карьерной истории в хронологическом порядке. Длительность строки — разница в месяцах между началом и концом; для текущей работы концом считается текущий месяц.

| Факт | Расчет |
|---|---|
| Общий профессиональный опыт | Сумма длительностей всех строк |
| Средняя длительность работы в компании | Общий опыт / число компаний (подряд идущие строки одной компании объединяются) |
| Количество переходов | Число смен компании между соседними строками |
| Количество внутренних повышений | Число соседних строк с той же компанией |

Факты показываются нейтрально, без оценки «хорошо» или «плохо». Если истории нет, выводится «Нет данных». Значения зависят от текущей даты, поэтому со временем растут.

## Сводка — `analysis(c)` и `summaryText(c)`

Строится только из введенных данных, без AI.

| Блок | Правило отбора |
|---|---|
| Сильные подтвержденные критерии | Статус «Подтверждено» и оценка ≥ 4; сортировка по оценке, затем по весу; первые 3 |
| Обязательные критерии с рисками | Обязательный критерий без данных, с оценкой 1–2, со статусом «Противоречивые данные» или «Требует проверки» |
| Критерии без данных | Все критерии без оценки |
| Подтвержденные риски (экран «Сравнение») | Оценка 1–2 или статус «Противоречивые данные» |
| Вопросы для следующего интервью | Непустые «Вопросы для проверки» из оценок (в порядке критериев) плюс «Вопросы для следующей проверки» из интервью; дубликаты по тексту убираются без учета регистра |

`summaryText()` собирает ту же информацию в простой текст для кнопки «Скопировать сводку» и добавляет в конец подпись о том, что решение принимает человек.

## Форматирование

| Функция | Пример |
|---|---|
| `tenge(2600000)` | `2 600 000 ₸` (`Intl.NumberFormat('ru-RU')`) |
| `pct(83.5)` | `84%`; `pct(null)` → `—` |
| `fmtDate('2026-10-14')` | `14.10.2026` |
| `dur(55)` | `4 года 7 мес.` |
